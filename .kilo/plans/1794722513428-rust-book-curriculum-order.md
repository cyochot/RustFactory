# Rust Book順へのカリキュラム再編

> 進捗: 実装・自動検証完了（2026-11-15）

## 目的と合意事項

- https://doc.rust-jp.rs/book-ja/ の第1〜20章を学習順とゲーム内章番号の基準にする。Rust Bookの各章内の節順も参考にし、既存ステージの内容を前提知識に沿って並べ直す。
- 384ステージを維持し、「学習ステージ → その時点までの知識で解けるパズル → 次の学習ステージ」を基本リズムにする。パズルは必要概念がすべて学習済みになる最も早い位置に置く。
- ゲーム内の `chapter`、`chapterTitle`、`displayId` は新しい学習順と一致させる。章内の表示番号はパズルも含めた順番で連番にする。全体の `index` も最終解放順で1〜384に連番にする。
- 現在の章グループは移行元の手掛かりに留め、個々の教材・パズルの実際のRust前提を確認して配置する。章ファイルのソース順を最終順序の根拠とし、実行時の旧章番号依存並べ替えを残さない。
- 全ステージのUUIDとステージ内容・パズル挙動は維持する。保存キーを更新し、進捗・保存コード・フリースタディ・ストーリー既読状態は新しいプレイ状態として初期化する。
- 物語を新しいステージ順・内容に合わせて章単位に再編する。既存UUIDとの紐付けを維持し、本文は原則活用して明確な不整合のみ調整する。物語のないステージには新しい物語を作成し、384ステージすべてを物語対象にする。

## 実装タスク

1. **全ステージの前提・学習対応表を作る**
   - 各UUIDについて教材/パズルの別、Rust Bookの対応章・節、使用するRust概念、必要な先行ステージを特定する。章タイトルや旧表示IDだけで分類せず、教材説明・starter/solution code・勝利条件を照合する。
   - 384件すべてを対応表に含め、Book本文の範囲外・複数章横断・既習概念の復習に当たる項目はその旨と配置根拠を記録する。
2. **解放順と章内番号を確定する**
   - 各章内ではRust Bookの節の順を基本に教材を整理し、必要な導入教材や復習は理解を妨げない位置に置く。
   - 全パズルについて前提概念を列挙し、最後の前提教材の直後をアンカーにする。複数Book章の前提がある場合は、すべての前提が出そろう最も早い位置、すなわち最後の前提を学ぶ章に置く。同じアンカーのパズルは前提の近さと難易度を考慮した決定的な順序にする。
   - 確定した全順序で章番号をRust Bookの1〜20に合わせ、各章内の教材とパズルに `章-連番` を付ける。教材の章、表示ID、実際の解放順が食い違わないことを対応表上で検査する。
3. **ステージデータを再構成する**
   - 全定義の `chapter`、`chapterTitle`、`displayId`、タイトルのID接頭辞、章番号を含むゲーム内教材表記を更新する。Rust Bookの実節番号を示す `bookSectionTitle` はBookの番号に正確に合わせる。Book外の独自教材は誤った節番号を付けず、説明用の中立的な表記にする。
   - 通常教材とパズルを同じ章ファイル内に新しい解放順で記述し、章ファイルを1〜20の順で集約する。全体の `index` を確定順に連番化する。
   - UUID、盤面、ステージ種別、解答・スターターコード、勝利条件を維持する。パズルの生成が表示ID・章番号・配列位置に依存している箇所はUUID等の安定キー基準へ切り離す。
4. **ストーリーを新しい教材順に対応させる**
   - 物語を新しい教育章の章別ファイルへ再編し、章タイトル・物語ログのグループを教材の新章と一致させる。各エントリーの `stageId` は既存UUIDのまま保つ。
   - 既存の本文は文脈が合うステージに維持し、明らかに内容・章の進行と矛盾する場合だけ修正する。物語エントリーのないステージには教材内容と学習体験に沿う導入・クリア後の物語を新規作成する。
   - 384件すべてに重複しないUUID参照の物語がちょうど1件あることを検証する。物語本文やログは教材章に基づき、新しい章・表示IDと矛盾しないことを確認する。
5. **進捗の初期化と表示を追随させる**
   - 進捗、フリースタディ、ストーリー既読のLocalStorageキーを新バージョンにし、旧保存データを読み込まない。初回起動は新しい全体順の最初のステージにする。
   - ステージ選択、次ステージ、自動再開、章フィルター、ロック判定、ストーリーログ等が新しい `ALL_STAGES` と章番号・表示IDを使うことを確認する。選択画面のカードには教材表示IDのみを表示する既存仕様を維持する。
6. **自動検証と回帰確認を更新する**
   - `scripts/verify-stages.ts` で384件、UUID/表示IDの一意性、index連続性、Book順の章1〜20、章内表示ID連番、各ステージの章・章タイトル一致、ソース配列と解放順の一致、ストーリー参照の網羅性・一意性を検証する。
   - 対応表の全パズルについてアンカーと前提教材の順序を自動またはデータ検査で確認し、未学習概念を使うパズルが先行しないことを検証する。
   - 全384件で既存の解答成功・スターター未クリア検証を維持する。`npm run verify:stages`、`npm run lint`、`npm run build`、`git diff --check` を実行する。

## リスク・注意点

- 現行の章番号はRust Bookの番号と異なる。対応表を先に作らず番号文字列だけを置換すると、章の誤分類、先行パズル、誤った節参照を生む。
- 複数Book章の知識を使うパズルは、最後の前提に合わせて後ろの章へ移る場合がある。教材上の分類・章番号もその配置に一致させる。
- 既存ステージ表示IDは変わるがUUIDを保つため、ストーリーと進捗内部キーをUUID基準に保つ。保存状態は合意どおりキー更新で初期化する。
- 物語が未設定のステージが多い場合は新規本文が大きなデータ追加になる。ステージUUIDごとの網羅表で漏れを防ぎ、既存の人物・口調・時系列との整合を検査する。
- Rust Book日本語版はRust 1.58以降を前提とした掲載版である。節構成・番号の参照元は指定URLに固定し、現行版との差異やBookにない独自教材は誤認しないよう明示する。
