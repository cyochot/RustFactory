# パズルを教材順へ統合する計画

## 目的と確定事項

- `puzzleAct` を通常教材の後ろに一括配置せず、解法に必要なRust概念を学んだ直後に出す。
- 必要な概念が複数なら、最後の前提となる通常教材の直後へ配置する。同じ挿入位置では、現在のパズル配列順を保つ。
- 前提を満たす教材が別の章・幕にある場合も、前提教材の直後を優先して配置する。
- 章・幕の所属と既存の章-番号（例 `3-25`）は、教材上の分類・表示用として維持する。
- `StageDefinition.id` は各ステージ固有の固定UUIDとし、実行時生成しない。旧章-番号は別フィールド（例 `displayId`）として保持する。
- 内部 `index` は統合後の全進行順で1から再採番する。次ステージ、自動再開、解放判定はこの順序を使う。
- 既存の進捗・保存コード・ストーリー既読データは互換移行せず初期化する。
- ステージアトラスは幕タブを維持し、選択幕のステージを全体進行順のフラットな一覧で表示する。各カードに教材章を表示する。

## 実装タスク

1. **識別子と表示の分離**
   - `StageDefinition` に旧章-番号用の表示IDを追加し、`id` を全384ステージの固定UUIDへ置換する。
   - 既存の章-番号文字列はタイトルやチャプター情報とともに表示・ストーリー対応に残す。UIでステージ番号を表示している箇所はUUIDではなく表示IDを使う。
   - ストーリー台本は既存の章-番号参照を維持し、ステージ表示IDからストーリーを解決する。進捗・既読状態などステージ単位の内部キーはUUIDへ統一する。
   - パズル挿入アンカーはUUIDではなく安定した表示IDで記述し、定義上の `id` 変更に影響されにくくする。

2. **進行順の構築**
   - 通常教材は現行の章順・教材順を維持し、各パズルに「直後へ挿入する通常教材の表示ID」を明示した配置表を用意する。
   - その配置表を使って通常教材列のアンカー直後へパズルを挿入し、同一アンカーのパズルは現在のソース配列順を維持する。
   - `ALL_STAGES` 構築時に全ステージの `index` を統合順で再採番し、現在のID数値ソートには依存しない。
   - 章・幕をまたぐ例も配置表どおりに処理する。たとえば `2-7`、`2-8` は `3-6` 後、Act 5の反復・関数パズルもそれぞれ `3-23`・`3-14` 後へ置く。`act` と `chapter` は元の教材上の所属を維持する。

3. **進行・保存・ストーリー参照の追随**
   - Appの最初の未クリアステージ、次ステージ遷移、Atlas/StoryLogのロック条件が、新しい `ALL_STAGES` と `index` を一貫して参照することを確認する。
   - ストーリー開始・再生・既読判定は表示ID経由で既存台本へ到達し、進捗等のキーはUUIDを使うよう参照箇所を更新する。
   - 進捗、フリースタディ、ストーリー既読のLocalStorageキーを新バージョンへ更新する。旧キーのデータは読まず、新しいプレイ状態を初期状態にする。

4. **アトラス表示**
   - 幕フィルター後、章グループ化を外して `ALL_STAGES` の進行順でフラット表示する。
   - 各カードには旧表示ID、タイトル、教材章を表示し、現在ステージへのジャンプ・フィルター・クリア/ロック表示は維持する。
   - 章アコーディオン操作を削除し、幕切り替え時に選択幕内の現在位置へ移動できるようにする。

5. **検証の更新**
   - ステージ検証に件数384、UUIDの一意性・固定形式、表示IDの一意性、indexの連続性を含める。
   - パズル挿入配置表の各アンカーが存在すること、アンカー後に配置されること、同一アンカーでのソース順維持を自動検証する。
   - 全ステージの解答コードがクリアし、スターターコードがクリアしない既存検証を継続する。
   - 型検査とステージ検証を実行し、アトラスの進行順・幕フィルター・章跨ぎステージ表示を確認する。

## リスク・注意点

- `id` はLocalStorage、クリア状態、ストーリー既読、各種コンポーネントのキーに広く使われている。内部UUIDと表示IDを混同せず、ストーリー台本の旧ID参照も壊さないこと。
- 既存タイトル文字列にも旧章-番号が含まれている。表示IDを追加した場合に同じ番号が二重表示にならないよう、タイトル表示箇所を確認する。
- `act`/`chapter` は教材・ストーリー上の所属であり、進行位置ではない。順序ソートに再利用しない。
- 配置表には、各パズルのRust前提をタイトル・コード・教材内容から推定した判断が含まれる。近似アンカー（`3-26`, `3-38`, `9-17`, `12-15`）は過度な遅延を避ける暫定判断として扱う。
- ストーリーログは現在ストーリー定義のあるステージを章別に表示する。進行可否は統合後のindexで判定し、Atlasのフラット進行順表示とは表示目的を区別する。
