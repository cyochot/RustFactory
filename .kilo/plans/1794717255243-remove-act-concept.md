# 幕の概念を削除する計画

## 目的と確定事項

- ユーザー向け表示とステージモデルから「幕」をなくし、「章」と「ステージ」のみで整理する。
- 20章の教材所属、章内のステージ順、全384ステージの統合進行順、パズル挿入位置、ストーリー本文は維持する。
- ステージの安定ID・表示ID・進捗・ストーリー既読データを維持し、保存キー変更やデータ移行は行わない。
- `act()`などRust教材の一般識別子は幕の意味ではないため変更しない。
- `stagesAct*.ts`等の内部ファイル名は維持するが、データ属性・UI状態・エクスポート名から幕を表す概念を除く。

## 実装タスク

1. **章・ステージUIへ統一**
   - `StageAtlasModal`の幕タブを除去し、全体進行順を既定表示にする。章フィルターは全章と各章の選択肢に置き換え、絞り込み後も各ステージの全体進行順を保つ。現在ステージへのジャンプ、種別・クリア状況フィルター、解放条件は維持する。
   - `StoryLogModal`の幕タブと幕単位のフィルターを除き、全ストーリーを章ごとの既存アコーディオンにまとめる。現在のステージが属する章を初期選択・ジャンプ先にする。章展開、解決状況フィルター、順次解放条件は維持する。
   - `App.tsx`から`initialAct`連携を除く。表示対象章は現在ステージの`chapter`で決める。

2. **幕の内部モデルを除去**
   - `StageDefinition.act`を型から削除し、通常ステージ・パズル全384件の定義から`act`値を除去する。
   - `ACT_META`、`STORY_ACT_META`、幕ベースのフィルター・初期状態・補助関数を廃止する。章情報は既存の`chapter` / `chapterTitle`を唯一の教材分類として使う。
   - 幕単位データを束ねるインポート・エクスポート名は、章範囲または中立的なデータセット名へ変更する。ファイル名自体は維持する。

3. **教材表記を整合**
   - ステージ名、導入文、トピックタグ、目標、ヒント、教材セクション、コア表示名などの「第N幕」表記を章・課題に即した中立表現に変更する。
   - 教材コードとクリア条件中の`ACT1 MASTER`、`ACT2_CLEAR`、`ACT3_DONE`等は対応箇所を一括して章または課題ベースの出力文字列へ置き換える。スターターコード、解答コード、`victoryCondition`、表示説明、ヒント間で文字列が一致することを確認する。
   - `ACT_META`由来の建物名・テーマ見出しは削除し、教材タイトルは章タイトルから表示する。
   - 物語本文そのものは改稿しない。ただしUIが幕を示す文言は除去する。

4. **検証**
   - 型検査で全ステージ定義・UI参照から`act`依存がなくなったことを確認する。
   - `npm run verify:stages`で384件、ID・表示ID一意性、連続index、通常教材順、パズル挿入順、全解答コードのクリア、スターターコードの未クリアを確認する。
   - `npm run lint`と`npm run build`を実行する。
   - リポジトリのアプリコードを検索し、「第N幕」「幕フィルター」「ACTn_...」など幕を指すユーザー向け文言・課題出力が残っていないことを確認する。Rustの`act()`等は除外する。
   - Atlasで全体順・章フィルター・現在位置ジャンプ、Story Logで20章表示・章展開・絞り込み・現在位置ジャンプを確認する。

## リスクと注意点

- 課題出力文字列を変更する場合、コード例だけでなく`stdoutIncludes`等の勝利条件とヒントも同時に更新しないとステージ検証に失敗する。
- パズルは前提教材直後へ挿入されるため、教材上の章（`chapter`）と統合進行上の位置は一致しない場合がある。章フィルターは`chapter`で行い、カード順は`index`で維持する。
- 現在の作業ツリーでは`StageAtlasModal.tsx`と`tsconfig.tsbuildinfo`に未コミット変更がある。実装時はAtlasの既存差分を読み込み、その変更を保持した上で章フィルターを統合する。
