# 解放順に合わせた章・ステージ番号の再採番

## 目的と確定方針

- ステージの既存統合解放順（通常教材とパズルの挿入順）を変えず、その順で章の初出順を決めて新1〜20章を割り当てる。
- 現行の初出順は旧1章、旧17〜20章、旧2〜16章。対応は旧1→新1、旧17〜20→新2〜5、旧2〜16→新6〜20。
- 各章に属するステージ（通常教材とパズル）は、統合解放順に章内番号を1から振り直し、新しい `章-番号` 表示IDにする。
- ステージ定義ファイルは新しい章ごとに1ファイルへ再編し、通常ステージとパズルを同じ章ファイル内で解放順に混在させる。種別によるファイル分離はしない。
- パズルを含む全ステージの挙動・盤面を維持する。パズル生成は旧章番号・旧番号から切り離し、既存UUIDを安定キーにしたレシピで再現する。
- Stage UUID、進捗・既読保存キー、通常教材とパズルの解放順は維持する。保存データ移行やLocalStorageキー変更は不要。
- ユーザー指定により、章番号付きの書籍節参照もゲーム内新章番号へ置換する。実際のRust本の章番号と不一致になることは了承済み。節内番号は維持する。

## 実装タスク

1. 現行の `ALL_STAGES` 解放順を基準に、一度限りの変換で各UUIDへ新章番号と章内連番を割り当てる。通常ステージ・パズルを含む各章の全定義を新しい章別ファイルへ移し、同一ファイル内で解放順に記述する。実行時の並べ替えや旧章番号からの変換に依存させない。
2. 全ステージデータの `chapter`、`chapterTitle`、`displayId`、タイトル番号、章見出し・関連するゲーム内章表記を新番号へ更新する。書籍節見出し中の章番号も対応する新番号に置換し、節内番号は保つ。コード内の数値、Rust概念、座標、文章中の非章番号は機械的に変更しない。
3. 旧 `puzzleAct*.ts` 群と通常ステージ別ファイルを廃止し、新しい章別定義ファイル群へ統合する。`puzzleAct5.ts` の番号依存生成はUUIDキーの明示レシピへ置き換える。各UUIDの現行パターン、距離、種別など挙動決定値を保持し、新表示IDや新章番号を変更しても同じ `StageDefinition` の盤面・解答・勝利条件が生成されるようにする。旧表示ID、旧章番号、旧パズル番号をレシピキー・生成入力として残さない。
4. パズル挿入アンカーの役割は、新章ファイル内での記述順に置き換える。表示IDをキーにした実行時挿入ロジックを除去し、章ファイルの順序を通常教材・パズルを含む全体解放順の唯一の根拠にする。
5. ストーリー台本を新しい表示IDに対応させるか、より安定するUUID基準のマッピングに移行する。ストーリー章タイトル、Story Log/Atlasの章選択・グループ表示、各画面のステージID表示とナビゲーションも新番号に揃える。
6. 検証を強化する。384件すべてのUUID/表示ID一意性、章番号1〜20の連続性、各章内表示IDが解放順に1から連続すること、章の初出が新番号順であること、ストーリー参照の解決、章ファイルの連結順と既存解放順が一致することを確認する。

## 影響範囲

- ステージ定義: 現行の `stagesAct*.ts` と `puzzleAct*.ts` を新1〜20章ごとに統合した章別ファイル群、および章ファイルを解放順に束ねる `src/data/stages.ts`。通常ステージとパズルの別ファイルは残さない。
- ストーリー参照: `src/data/storyAct1.ts`〜`storyAct5.ts`、`src/data/storyScripts.ts`、必要に応じて `src/App.tsx`。
- 表示: `src/components/StageAtlasModal.tsx`、`StoryLogModal.tsx`、`StoryNovelOverlay.tsx`、`StageModals.tsx`、`CanvasArena.tsx`、`TitleScreen.tsx` など表示ID・章見出しを出す箇所。
- 検証: `scripts/verify-stages.ts`。
- `StageDefinition.id` のUUIDを変更しない。既存保存データの進捗・コード・ストーリー既読状態は維持する。

## リスクと検証

- 章内番号の再割当てで表示IDが変わるため、表示IDをキーにしているストーリー検索をUUID基準にするか、全参照を漏れなく一括更新する。パズルは別の挿入表に頼らず章ファイル上の順序に含める。
- 新章番号を生成条件に使うとパズルが変わるため、UUID別レシピの全出力を変更前と照合する。既存UUID、盤面、ステージ種別、解答コード、勝利条件を維持する。
- 書籍節番号は指定に従って新章番号へ変わるため、Rust本の実際の章節番号とは異なる。章番号の置換のみとし、節内番号や教材内容を誤変更しない。
- `npm run verify:stages`、`npm run lint`、`npm run build` を実行する。検証では全解答がクリアし、スターターがクリアしない既存条件も維持する。
- 最後にアプリコード内の旧 `章-番号`、旧章見出し、旧番号を用いたストーリー・アンカー・生成参照を検索し、残存が意図した書籍内容でない限り解消する。
